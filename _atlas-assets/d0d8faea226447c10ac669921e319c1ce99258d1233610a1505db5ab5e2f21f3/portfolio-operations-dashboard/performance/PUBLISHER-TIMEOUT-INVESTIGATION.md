Available evidence does **not** prove that the failed REST requests used an eight-second timer or a 30-second timer. No timeout/configuration defect has been established, so no software/configuration fix or compute change is justified by this investigation alone.

## Mechanism and possible failure modes

PostgREST hoists allowed routine settings before the main RPC query; those settings override the role defaults. The default allowlist includes `statement_timeout`. Supabase explicitly documents this function-level REST exemption. Therefore the normal authenticated/authenticator 8s defaults do not independently cap a correctly hoisted 30s RPC. [PostgREST transactions](https://postgrest.org/en/stable/references/transactions.html#hoisted-function-settings), [configuration](https://postgrest.org/en/stable/references/configuration.html#db-hoisted-tx-settings), [Supabase timeouts](https://supabase.com/docs/guides/database/postgres/timeouts#function-level).

The version-pinned implementation corroborates this: 14.5 defaults include the timeout; schema-cache loading filters `pg_proc.proconfig` through the allowlist; request setup applies the cached routine settings after role settings. A configured pre-request hook runs afterward and could change them. Thus an effective allowlist excluding the timeout, a stale/incorrect cached routine entry, or a later hook override could leave a different timer. None is demonstrated by the observed catalog values. [14.5 config](https://github.com/PostgREST/postgrest/blob/v14.5/src/PostgREST/Config.hs), [schema loader](https://github.com/PostgREST/postgrest/blob/v14.5/src/PostgREST/SchemaCache.hs), [request setup](https://github.com/PostgREST/postgrest/blob/v14.5/src/PostgREST/Query/PreQuery.hs).

PostgreSQL starts the statement deadline with query-protocol processing, rather than browser request start. Function SET clauses also apply on function entry independently of REST hoisting. Consequently merely returning `current_setting('statement_timeout')` from inside the publisher would not distinguish an inherited transaction setting from its own entry setting. PGlite/direct SQL and the existing catalog checks are not REST-hoisting acceptance. [PostgreSQL 17 timeout semantics](https://www.postgresql.org/docs/17/runtime-config-client.html#GUC-STATEMENT-TIMEOUT), [function SET semantics](https://www.postgresql.org/docs/17/sql-createfunction.html).

## Smallest safe next step and conditional remedy

Request an operator-side **read-only, allowlisted** check of the running REST process's effective `db-hoisted-tx-settings`, configured pre-request/pre-config names, and only this publisher's `pdFuncSettings` from the runtime schema cache. Do not export complete configuration or JWT/connection settings. PostgREST exposes runtime schema cache through its operator admin endpoint; access to that endpoint is not available through the enabled project tools. [Admin schema-cache endpoint](https://postgrest.org/en/stable/references/admin_server.html#runtime-schema-cache).

If the effective allowlist contains the timeout but the publisher's cached entry omits or misstates 30s, a single schema-cache reload followed by target-entry verification is a narrower remedy than changing deadlines or restarting the project. If the effective allowlist excludes it, correct only that omission while preserving the existing allowlist, then reload configuration/schema and verify the target. If a pre-request hook resets this route's timer, review a route-specific correction while retaining its authorization behavior. These are conditional proposals, not actions performed. [Schema-cache reloading](https://postgrest.org/en/stable/references/schema_cache.html#schema-cache-reloading-with-notify).

If the runtime cache/settings cannot be inspected, the next proof would require a separately reviewed, administrator-only, non-writing HTTP diagnostic that distinguishes execution beyond the role deadline; a quick setting echo is insufficient. No diagnostic RPC, sleep query, reload, configuration change, larger publication retry or compute change was created/executed here. Successful hoisting would still not prove that the full publication fits the declared deadline.

The current Supabase changelog index was checked; no relevant breaking change removing function-timeout support was identified. The current “stable” PostgREST documentation is version 16, so the core behavior above was additionally checked against the actual deployed 14.5 source tag.
